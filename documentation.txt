                    FIERO-HOTSPOT v0.4 - RELEASE NOTES

Version:      v0.4 (Runtime Intelligence)
Focus:        Active RF Validation, Pre-flight Guardrails, UI Branding
Target Distros: Arch/Garuda, Debian/Ubuntu, Fedora

================================================================================
1. OVERVIEW OF CHANGES
================================================================================
v0.4 introduces active runtime channel intelligence to fiero-hotspot. While v0.3
focused on installer-level discovery and hardware auditing, v0.4 actively validates
the current upstream Wi-Fi channel against the hardware-supported broadcast list
before launching create_ap. This prevents kernel driver panics, -EINVAL firmware
rejections on DFS/no-IR frequencies, and ghost interface lockups.

================================================================================
2. DETAILED CHANGELOG BY FILE
================================================================================

[ install.sh ]
--------------------------------------------------------------------------------
* RF Spectrum Regex Hardening:
  - Updated the PHY frequency parsing pattern to support kernel drivers that
    report frequency values with floating-point decimals (e.g., '2412.0 MHz'):
      iw phy "$PHY" info | grep -E '\* [0-9]+(\.[0-9]+)? MHz \[[0-9]+\]' ...
  - Resolves empty channel list fallbacks on Intel Wi-Fi chipsets (iwlwifi).

[ fiero-hotspot.sh ]
--------------------------------------------------------------------------------
* Runtime Channel Pre-Flight Validation:
  - Added delimiter-padded string validation directly following upstream channel
    detection:
      if [[ ",$SUPPORTED_CHANNELS," != *",$CHANNEL,"* ]]; then ...
  - Automatically intercepts connection attempts on restricted channels (e.g.,
    lower 5 GHz UNII-1 'no IR' channels 36-48, or DFS channels 52-144).
  - Emits an explicit error to journald:
      [ERR] Channel $CHANNEL is not supported for AP broadcast on this hardware.
  - Aborts safely with exit code 0 before touching create_ap or virtual interfaces,
    preventing systemd unit crash flags.

* UI & Desktop Notification Branding:
  - Injected application name parameter '-a "Fiero Hotspot"' across all notify-send
    invocations.
  - Replaces generic notification headers ('notify-send') with proper application
    branding across KDE Plasma, GNOME, and standalone notification daemons.
  - Added dedicated rejection notification:
      "Hotspot not started: Channel $CHANNEL is unsupported"

[ UNTOUCHED ASSETS ]
--------------------------------------------------------------------------------
* 99-fiero-hotspot.rules: Stable (Udev power supply trigger unchanged).
* fiero-hotspot.service : Stable (Type=forking systemd unit unchanged).
* uninstall.sh          : Stable (Cleanly purges all files and rules).

3. RUNTIME GUARDRAIL BEHAVIOR MATRIX
================================================================================

Trigger / Condition       Script Action             Desktop Notification
--------------------------------------------------------------------------------
AC Power Disconnected     exit 0 (Graceful abort)   "Hotspot not started: charger not connected"
Wi-Fi Interface Down      exit 0 (Graceful abort)   "Hotspot not started: WiFi is off"
Wi-Fi Not Connected       exit 0 (Graceful abort)   "Hotspot not started: not connected to WiFi"
Channel Detect Failed     exit 0 (Graceful abort)   "Hotspot not started: channel detect failed"
Unsupported AP Channel    exit 0 (Graceful abort)   "Hotspot not started: Channel <X> is unsupported"

Charger Unplugged (udev)  Tears down ap0 / clean    "Hotspot stopped (charger unplugged)"

4. CONFIGURATION SPECIFICATION (/etc/fiero-hotspot.conf)
================================================================================
Permissions: 600 (root:root)

Key                  Type     Description
--------------------------------------------------------------------------------
SSID                 string   Broadcast SSID for the virtual AP
PASSWORD             string   WPA2 pre-shared key (>= 8 characters)
INTERFACE            string   Physical Wi-Fi interface (e.g., wlo1)
POWER_SUPPLY         string   Mains AC power supply identifier (e.g., AC0)
SUPPORTED_CHANNELS   string   Comma-separated list of non-DFS broadcast channels

================================================================================
5. VERIFICATION & TESTING PROCEDURE
================================================================================
1. Upgrade installation:
   $ sudo ./install.sh

2. Negative Test (Unsupported Channel Interception):
   - Connect laptop to a 5 GHz Wi-Fi network on channels 36-144 (DFS / no IR).
   - Plug in AC charger or execute: $ sudo systemctl start fiero-hotspot.service
   - Verify UI notification: "Hotspot not started: Channel <X> is unsupported"
   - Confirm clean journal log: $ sudo journalctl -u fiero-hotspot.service -n 20

3. Positive Test (Active Virtual AP Broadcast):
   - Connect laptop to a 2.4 GHz (channels 1-13) or high 5 GHz (149-165) network.
   - Plug in AC charger.
   - Verify UI notification: "Hotspot is live! SSID: <SSID>"
   - Verify client connectivity and DHCP lease assignment.
